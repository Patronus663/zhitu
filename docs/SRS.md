# 知途（ZhiTu）软件需求规格说明（SRS）

> 文档编号：ZhiTu-SRS-2026-001 · 版本：v1.0 · 状态：定稿
> 适用对象：开发、测试、产品、维护人员

---

## 1. 引言

### 1.1 编写目的
本文档定义「知途」智能学习 App 的功能需求、非功能需求与约束条件，作为开发、测试、验收的共同依据。

### 1.2 项目背景
「知途」是面向**南京大学学生**的错题整理 + AI 学情分析 + 学习计划 + 智能检索一站式学习助手。核心价值在于让 AI 持续反哺学习，形成「错题数据 → AI 判题/错因 → 云端题库 → 检索/学情 → 计划 → 答疑」的闭环。

### 1.3 术语定义
| 术语 | 说明 |
| --- | --- |
| 云端题库 | 全局共享的 `questions` 题目表，含内置真题与用户贡献 |
| 个人错题库 | 每个用户关联的 `user_questions` 错题记录 |
| 学情 | 存储于 `learning_profiles` 的个性化学习画像长文本 |
| SSE | Server-Sent Events，服务端流式推送 |
| AI 判题 | 使用大模型对错题进行解答、错因与标签分析 |

### 1.4 参考资料
- GB/T 8567-2006 计算机软件文档编制规范
- README.md（项目根目录）

## 2. 总体描述

### 2.1 产品定位
一款面向大学生、以错题为核心的 AI 学习助手，兼容 Android / iOS / Web 三端。

### 2.2 运行环境
| 项 | 要求 |
| --- | --- |
| 前端 | Expo 54 / React Native 0.81 / React 19 |
| 后端 | Node.js（Express.js，ESM + TypeScript） |
| 数据库 | Supabase（PostgreSQL） |
| AI | 豆包 doubao-seed 大模型 + 联网搜索 |

### 2.3 用户角色
| 角色 | 说明 |
| --- | --- |
| 访客（未登录） | 仅可浏览登录页与引导页，无法使用业务功能 |
| 普通学生用户 | 已注册登录，可使用全部学习功能 |

## 3. 功能需求

### 3.1 账号与引导
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-1.1 | 邮箱注册/登录 | 基于 Supabase Auth，登录页支持登录/注册切换 |
| FR-1.2 | 登录态持久化 | session 写入 AsyncStorage，重启保持登录 |
| FR-1.3 | 首次引导 | onboarding 收集称呼、专业、年级、学习目标等，初始化学情 |

### 3.2 错题整理
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-2.1 | 拍照/文字录入 | 支持拍照或文本描述题目 |
| FR-2.2 | 图像识别 | `POST /analyze-image` 将图片转为题目文字 |
| FR-2.3 | AI 判题与解答 | `POST /ai-answer` 给出解答、错因分析（可用于自我训练） |
| FR-2.4 | 标签生成与校验 | AI 生成学科/知识点/方法/难度标签，`validate-tags` 校验用户修改 |
| FR-2.5 | 错题录入 | 写入云端 `questions` + 个人 `user_questions`，错因写入学情 |
| FR-2.6 | 照片上传 | 本地 URI 照片上传为公网 URL，录入后可回显查看 |

### 3.3 题目检索
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-3.1 | 范围选择 | 云端题库 / 个人错题范围检索 |
| FR-3.2 | 自然语言检索 | 输入学科、知识点、方法、数量描述，AI 解析意图按相关性/评分检索 |
| FR-3.3 | 联网补充 | 题库不足时调用联网搜索，并标注"来源于网络" |
| FR-3.4 | 题目评分 | 支持 1-5 分评分，动态调整推荐权重 |
| FR-3.5 | 反馈有误 | 反馈题目错误，供系统纠错 |

### 3.4 学情分析
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-4.1 | 学情读取 | `GET /learning/:user_id` 返回学情画像 |
| FR-4.2 | AI 学情分析 | 结合学情与计划生成建议 |
| FR-4.3 | 学情修正 | 用户文字/语音反馈修正学情 |

### 3.5 学习计划
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-5.1 | AI 生成计划 | `POST /generate` 依据用户情况生成学习计划 |
| FR-5.2 | 计划类型 | `daily`（今日任务切入首页）与 `long_term`（长期计划进"我的计划"） |
| FR-5.3 | 任务跟进 | 今日/本周任务展示、完成打勾、进度统计 |
| FR-5.4 | 逾期迁移 | 逾期任务可一键迁移到今日 |
| FR-5.5 | 任务管理 | 计划的增删改、任务项的增删改、移动/延后日期 |

### 3.6 智能问答（和知途聊聊）
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-6.1 | 流式对话 | SSE 流式返回 AI 回答，逐字展示 |
| FR-6.2 | 个性化上下文 | 对话结合用户学情/计划 |
| FR-6.3 | 历史记录 | 保存并按时间获取聊天记录，支持清空 |

## 4. 数据需求（DRD 摘要）

数据统一存储于 Supabase PostgreSQL，共 10 张核心表：
`health_check`、`users`、`questions`、`user_questions`、`learning_profiles`、`study_plans`、`plan_items`、`chat_messages`、`usage_records`。

（完整字段与关系见《架构与设计文档》）

---

## 5. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-1 | 性能 | 检索与判题接口在 AI 响应时间可接受内返回；聊天流式边生成边输出 |
| NFR-2 | 可用性 | 三端（Android/iOS/Web）一致体验 |
| NFR-3 | 安全性 | 上传目录生产环境落于可写临时区 `/tmp`，目录创建失败不阻塞服务 |
| NFR-4 | 兼容性 | 基于 Expo 官方库，避免原生构建风险 |
| NFR-5 | 可维护性 | 前后端分离，遵循 `/api/v1` 统一前缀与分层结构 |

---

## 6. 约束与环境

- 后端所有 API 使用统一前缀 `/api/v1`。
- 前端调用后端必须使用系统注入的 `EXPO_PUBLIC_BACKEND_BASE_URL`。
- 已知待改进（非本期范围）：业务接口 `x-session` 鉴权补齐、后端 service 层抽离、外键级联与 migrations。

---

## 7. 验收标准
1. 注册/登录/引导流程可完成闭环。
2. 错题录入可上传照片且录入后照片可正常查看。
3. 检索可返回云端/个人/联网结果。
4. 计划可创建、跟进任务、迁移逾期。
5. 聊天以 SSE 流式输出且历史可回查。
6. 生产环境部署不再因上传目录权限崩溃。
