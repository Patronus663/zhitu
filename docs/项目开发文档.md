## 1. 概述

### 1.1 项目背景

"知途"是一款专为南京大学学生打造的智能学习 App，围绕"练题、分析、规划、问答"四大核心场景，利用大语言模型（LLM）与语义检索能力，提供个性化学习辅助。系统覆盖题库搜索、学情分析、学习计划制定、AI 学习助手问答等功能，帮助学生在学习过程中即时查漏补缺、动态调整学习策略。

### 1.2 项目目标

- 提供一站式学习工具：往期/模拟题搜索与练习、个人错题本与掌握度跟踪。
- 通过生成式 AI 实现"学情画像 + 个性化建议 + 学习规划 + 即时问答"。
- 数据云端持久化，支持收藏、进度、偏好在不同设备间同步。

### 1.3 技术选型

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Expo 54 + React Native + Expo Router | 移动优先，兼容 iOS/Android/Web |
| 样式 | Tailwind CSS（Uniwind 实现） | 原子化样式，支持组件级设计令牌 |
| 后端 | Express.js（TypeScript，ESM） | RESTful API，统一 `/api/v1` 前缀 |
| 数据库 | PostgreSQL + Drizzle ORM（Supabase） | 结构化数据持久化 |
| 大模型 | 豆包（Doubao）Seed 系列 | 多轮对话、学情分析、规划生成（流式 SSE） |
| 搜索 | 语义检索 + Web 搜索 | 学习内容检索与在线补充 |
| 静态资源 | 本地 assets + 对象存储 | 图片等多媒体存取 |

### 1.4 文档约定

- 接口错误码统一格式：`{ "code": number, "message": string }`。
- 所有时间字段默认返回 ISO 8601 字符串；日期字符串为 `YYYY-MM-DD`。
- 布尔字段：`true/false`。

## 2. 可行性研究与项目计划

### 2.1 可行性分析报告

#### 技术可行性
- 前后端技术栈成熟（Expo/React Native + Express），社区生态完善。
- 生成式 AI 能力通过 `coze-coding-dev-sdk` 接入，支持流式输出（SSE），满足对话式体验。
- PostgreSQL 支持复杂关联查询与 JSON 扩展，适合灵活的学习数据模型。
- **结论：技术路线成熟，可行。**

#### 经济可行性
- 前端使用 Expo Go 即可调试，无需立即投入原生工程成本。
- 数据库与 AI 依赖可按调用量/容量弹性计费，初期门槛低。
- **结论：中低成本起步，可行。**

#### 法律可行性
- 题库内容需确保授权与合规，涉及版权内容应取得授权或使用公开/自建数据。
- 用户隐私数据（学情画像、聊天记录）需遵守《个人信息保护法》，需提供隐私政策与授权留存。
- **结论：在合规治理前提下可行。**

## 3. 需求分析（软件需求规格说明 SRS）

### 3.1 用户角色

| 角色 | 描述 |
|------|------|
| 访客（未登录） | 可浏览题库、使用部分搜索能力 |
| 学生（已登录） | 完整功能：练题、错题本、学情画像、学习计划、AI 问答、云端同步 |

### 3.2 功能需求

#### FR-1 题库搜索与练习
- 按学科、难度、知识点检索题目；查看题目内容并作答。
- 记录作答结果（正确/错误）、错误分析与掌握状态。

#### FR-2 错题本（个人题库）
- 展示当前用户加入的题目，支持标记"已掌握"。
- 展示个人知识点的掌握情况。

#### FR-3 学情分析
- 依据用户作答、学习画像生成"优势/薄弱/习惯/错误模式"分析。
- 提供个性化学习建议与薄弱知识点清单。
- 登录后可同步云端收藏与进度。

#### FR-4 学习计划
- 制定每日/长期学习计划，含开始与结束日期。
- 计划下可添加多项任务（计划项），支持勾选完成与排序。
- 主页展示"今日任务"与"本周计划"。

#### FR-5 AI 学习助手（知途聊聊）
- 多轮问答，支持上下文理解。
- 支持流式（逐字）输出，提升交互反馈。
- 可基于用户学习画像给出针对性建议。

#### FR-6 用户系统
- 注册/登录、用户信息（昵称、专业、年级）设置与完善。
- 学习目标、掌握期望、个性化信息采集。
- 云端同步用户收藏与学习进度。

### 3.3 性能需求

| 指标 | 目标 |
|------|------|
| API 响应 | 常规读写 < 300ms（不含外部 AI 调用） |
| AI 问答首包 | 流式输出，首字 < 2s |
| 并发 | 支持多用户并行查询，数据库索引覆盖热查询 |

### 3.4 安全需求

- 接口统一 CORS 与 JSON 解析，限制请求体大小（50MB）。
- 用户归属数据（错题、计划、画像、聊天）均按 `user_id` 隔离并建立索引。
- 涉及第三方（Web 搜索、对象存储）返回的 URL 需校验来源，防钓鱼与注入。
- 部署环境需配置 HTTPS、密钥管理，避免明文凭据入库（存储于环境变量）。

## 4. 系统架构设计（系统/子系统设计说明）

### 4.1 分层架构

```
┌───────────────────────────────────────────────┐
│  Expo 54 + React Native (client/)             │
│  · Expo Router 路由 · screens 页面 · Tailwind │
└──────────────────┬────────────────────────────┘
                   │ HTTP / API（/api/v1）
┌──────────────────▼────────────────────────────┐
│  Express.js 后端 (server/src)                  │
│  · routes/    路由层（users/questions/search/  │
│                learning/plans/chat）            │
│  · services/  LLM 等外部服务                   │
│  · storage/   数据访问层（Drizzle/Supabase）   │
└───────┬────────────────────────────┬───────────┘
        │                            │
┌───────▼────────┐         ┌─────────▼───────────┐
│ PostgreSQL     │         │ 豆包 LLM / 搜索 /     │
│ (Supabase)     │         │ Web Search / 存储     │
└────────────────┘         └─────────────────────┘
```

### 4.2 模块划分

| 子模块 | 职责 |
|--------|------|
| `client/screens/` | 页面实现（home 主页、search 题库搜索、plan-create 计划、chat 聊聊、profile 学情分析） |
| `client/components/` | 可复用组件（Screen 容器等） |
| `client/hooks/` `contexts/` | 自定义 Hook、全局状态（认证等） |
| `server/src/routes/` | HTTP 路由与参数校验 |
| `server/src/services/` | 外部能力封装（LLM 等） |
| `server/src/storage/` | 数据访问、迁移/Schema |

### 4.3 关键设计决策

- **前后端分离**：前端通过统一 `EXPO_PUBLIC_BACKEND_BASE_URL` 访问后端，接口路径统一 `/api/v1`。
- **流式优先**：AI 对话采用 SSE 流式接口，前端以 `react-native-sse` 消费，实现逐字呈现。
- **路由一致性**：`client/app/` 仅做路由 re-export，`client/screens/` 承载实现，保证 Tab 与页面文件一一对应。
- **路由顺序治理**：Express 静态路由置于动态路由前，通配符置于末尾，避免匹配覆盖。

## 6. 数据库设计说明

> 依据 `server/src/storage/database/shared/schema.ts`（Drizzle ORM / PostgreSQL）。

### 6.1 数据模型总览（ER 关系）

```
users 1─N user_questions N─1 questions
users 1─N learning_profiles
users 1─N study_plans 1─N plan_items
users 1─N chat_messages
users 1─N usage_records
health_check（系统表）
```

### 6.2 表结构

| 表名 | 关键字段 | 说明 |
|------|---------|------|
| `users` | id(uuid pk), nickname, major, grade, learning_goal, mastery_expectation, personalized_info, is_onboarded, created_at, updated_at | 用户与学习偏好 |
| `questions` | id, content, answer, images(jsonb), subject, question_type, knowledge_points(jsonb), methods(jsonb), difficulty, rating, rating_count, is_active, created_by, created_at | 云端共享题库 |
| `user_questions` | id, user_id, question_id, wrong_answer, error_analysis, is_mastered, created_at | 用户错题本/个人题库 |
| `learning_profiles` | id, user_id, strengths, weaknesses, learning_habits, error_patterns, mastered_points, weak_points, updated_at | 学情画像 |
| `study_plans` | id, user_id, title, description, start_date, end_date, is_active, plan_type('daily'/'long_term'), created_at | 学习计划 |
| `plan_items` | id, plan_id, title, description, due_date, is_completed, completed_at, sort_order | 计划项 |
| `chat_messages` | id, user_id, role, content, created_at | AI 对话记录 |
| `usage_records` | id, user_id, action_type, detail, created_at | 使用/行为记录 |
| `health_check` | id, updated_at | 系统健康表 |

### 6.3 索引策略

- 用户维度：`users(id)`、各关联表 `user_id` 均建索引。
- 查询维度：`questions` 对 `subject/difficulty/rating/is_active/created_at/created_by` 建索引。
- 时间维度：`users/chat_messages/usage_records` 的 `created_at` 建索引。
- 业务维度：`plan_items` 按 `plan_id/due_date/is_completed`，`study_plans` 按 `user_id/is_active/plan_type`。

### 6.4 完整性约束

- 主键/外键引用关系保证数据一致性（`plan_items.plan_id → study_plans.id` 等）。
- 布尔、日期、JSON 类型均有明确默认值约束。

## 7. 接口设计说明

> 统一前缀：`/api/v1`；请求/响应均为 JSON；错误格式 `{ code, message }`。

### 7.1 通用约定

- 认证：通过请求头或用户标识注入 `user_id`（当前按会话/设备标识关联用户）。
- 分页/筛选：搜索类接口支持 `subject`、`difficulty`、`keyword` 等查询参数。
- 时间：`created_at/updated_at` 为 ISO 8601；`start_date/end_date` 为 `YYYY-MM-DD`。

### 7.2 用户与画像

| 方法 | 路径 | 参数 | 返回值 |
|------|------|------|--------|
| POST | `/users/register` | `{ nickname, major?, grade? }` | 用户对象 |
| POST | `/users/login` | `{ nickname }` | 用户对象 + 标识 |
| GET | `/users/me` | Header 标识 | 当前用户信息 |
| PUT | `/users/me` | `{ nickname?, major?, grade?, learning_goal?, mastery_expectation?, personalized_info? }` | 更新后用户 |
| PUT | `/users/onboarding` | `{ ... }` | 完成引导信息 |
| GET | `/learning/profile` | `user_id` | 学情画像 |
| PUT | `/learning/profile` | `user_id, { strengths?, weaknesses?, ... }` | 更新画像 |
| POST | `/learning/analyze` | `user_id` | 触发 AI 学情分析与建议 |

### 7.3 题库与作答

| 方法 | 路径 | 参数 | 返回值 |
|------|------|------|--------|
| GET | `/questions` | `subject?, difficulty?, keyword?, page?` | 题目列表 |
| GET | `/questions/:id` | — | 题目详情 |
| GET | `/questions/me` | `user_id` | 用户错题/收藏列表 |
| POST | `/questions/me` | `user_id, question_id, wrong_answer?, error_analysis?` | 加入个人题库 |
| PUT | `/questions/me/:id/mastered` | `is_mastered` | 更新掌握状态 |
| POST | `/questions/:id/feedback` | `rating` | 题目打分，联动评分 |

### 7.4 搜索与反馈

| 方法 | 路径 | 参数 | 返回值 |
|------|------|------|--------|
| GET | `/search` | `keyword, subject?` | 搜索结果（题目/百科） |
| POST | `/search/feedback` | `{ ... }` | 记录搜索相关性反馈，联动评分 |

### 7.5 学习计划

| 方法 | 路径 | 参数 | 返回值 |
|------|------|------|--------|
| GET | `/plans` | `user_id, active?` | 计划列表（含项） |
| POST | `/plans` | `user_id, title, description?, start_date?, end_date?, plan_type?` | 创建计划 |
| GET | `/plans/:id` | — | 计划详情 |
| PUT | `/plans/:id` | 更新字段 | 更新计划 |
| DELETE | `/plans/:id` | — | 删除计划 |
| POST | `/plans/:id/items` | `{ title, description?, due_date? }` | 新增计划项 |
| PUT | `/plans/items/:itemId` | `is_completed?` | 勾选完成/更新项 |
| DELETE | `/plans/items/:itemId` | — | 删除项 |

### 7.6 AI 助手（流式）

| 方法 | 路径 | 参数 | 返回值 |
|------|------|------|--------|
| POST | `/chat` | `{ user_id, messages: [{ role, content }] }` | SSE 流：逐块内容，`[DONE]` 结束 |
| POST | `/chat`（带上下文） | 补充历史消息/画像 | 结合上下文流式回答 |

> **SSE 头部约定**：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`Connection: keep-alive`；结束标记 `data: [DONE]`。

## 8. 实现与测试计划

## 10. 软件用户手册（功能操作说明）

### 10.1 主页

- **今日任务 / 本周计划**：查看当前计划与待办，点击可进入计划管理。
- **快捷入口**：进入题库搜索、学情分析、制定计划、AI 问答。
- 背景为淡紫肌理图，卡面半透明白，主色深紫/浅灰蓝。

### 10.2 题库搜索

- 输入关键词或按学科筛选，点击搜索展示结果。
- 对题目可作答、加入错题本；可对搜索结果反馈有用性。

### 10.3 制定与执行计划

- 进入"制定计划"填写标题、时间、类型（每日/长期）。
- 创建成功后提示"您已创建计划"，可回到计划页新增计划项、勾选完成。

### 10.4 学情分析与收藏同步

- 查看学情画像（优势、薄弱、习惯、错误模式）与个性化建议。
- **账号登录后**可同步云端收藏与学习进度（错题、进度、偏好多端一致）。

### 10.5 AI 学习助手（知途聊聊）

- 打开聊天页进入对话，发送学习相关问题，AI 流式回复。
- 顶部头像为知途品牌形象；空态引导"开始和知途对话吧"。

## 11. 计算机操作手册（部署、运维、故障排查）

### 11.1 环境依赖

- Node.js（模板要求 Node ≥ 某个支持 ESM 的稳定版），pnpm 包管理。
- 数据库：PostgreSQL（Supabase 托管或自建）。
- 前端 SDK：Expo 54 + React Native。

### 11.2 环境变量

| 变量 | 说明 |
|------|------|
| `EXPO_PUBLIC_BACKEND_BASE_URL` | 前端访问后端的 Base URL，由系统注入，勿自行覆盖 |
| 数据库/第三方凭据 | 通过 Supabase 与 SDK 配置注入环境变量 |

### 11.3 启动与重启

```bash
# 首次启动 / 重启前后端（会自动清理占用端口进程）
coze dev

# 前端仅静态导出（Web）
cd client && npx expo export --platform web

# 后端开发模式（内部已 kill 旧进程）
cd server && NODE_ENV=development pnpm run dev
```


### 11.5 故障排查

| 现象 | 排查建议 |
|------|----------|
| 页面白屏/路由不匹配 | 检查 `client/app/` 与 `screens/` 一致性；是否有 `(tabs)/index.tsx`；删除多余 `app/index.tsx` |
| 背景/样式不更新 | 重启前端服务并清缓存（HMR 对样式可能滞后） |
| API 500 | 查看 `/app/work/logs/bypass/app.log`；触发一次请求后再 `tail` 最新日志 |
| 端口占用 | 用 `coze dev` 重启（自动清理） |
| 图片背景只显示局部 | 确认使用 `ImageBackground` + `resizeMode="cover"` 满幅承载 |

## 12. 项目开发总结报告

### 12.1 完成情况

- 已实现题库搜索、错题/个人题库、学情分析、学习计划、AI 学习助手、用户系统（登录后云端同步收藏与进度）等核心功能。
- 前端采用 Expo Router + Tailwind，后端 Express + Drizzle + Supabase，集成豆包 LLM（SSE 流式）与搜索能力。
- 页面视觉经多轮迭代：统一淡紫肌理背景，卡片半透明白，辅助色浅灰蓝，主色深紫，整体风格柔和高级。

### 12.2 取得的经验与不足

**经验**
- 前后端分离 + 统一 API 前缀使功能可独立演进、并行开发。
- 流式（SSE）+ 轮询的模式适合 AI 与异步长任务，体验优于一次性返回。
- 静态检查、路由一致性工具能在交付前拦截大量结构性问题。

**不足与后续优化**
- 自动化测试（单测/端到端）覆盖率待提升。
- AI 生成内容需更强的合规与格式校验。
- 账号体系当前侧重单标识关联，后续宜引入正式认证（手机号/邮箱、JWT、OAuth）。
- 视觉回归建议引入截图对比，避免样式缓存带来的假回归。

### 12.3 结论

"知途"已达到预期的核心功能闭环与稳定的迭代交付节奏。数据模型、接口设计、前端架构具备清晰的可扩展性，后续可在认证完善、测试体系、内容合规与视觉质检方面继续深化。
